## 2024-05-14 - Fix command injection in Reconciler
**Vulnerability:** A command injection vulnerability was present in the reconciler (`packages/core/src/reconcile.ts`). The `execSync` function was used to perform syntax checking on a temporary file path with string interpolation (`node --check "${tempFile}"`). While `tempFile` itself was relatively constrained, an attacker could potentially manipulate the workspace path to inject arbitrary shell commands.
**Learning:** This codebase previously relied on `execSync` which invokes a shell interpreter, making it vulnerable to command injection if paths are not completely sanitized. Always avoid string-based command execution when user input or variable paths are involved. Furthermore, when refactoring to avoid shell usage, `execFileSync` is often a safer drop-in replacement than `spawnSync` because it preserves the exact Error object structure that existing `try...catch` blocks expect.
**Prevention:** Replaced `execSync` with `execFileSync(process.execPath, ["--check", tempFile])` which avoids shell interpretation altogether by passing arguments as an array directly to the executable. Prefer `execFileSync` over `execSync` to prevent command injection while maintaining error handling compatibility.
